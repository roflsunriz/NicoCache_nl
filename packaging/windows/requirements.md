# Windows インストーラー完成条件

通常のWindowsインストール手順から、アプリを利用可能な場所へ安全に配置し、
更新・修復・削除できるところまでをインストーラーの責務とする。証明書、
Windowsプロキシー、自動起動など、利用者のOS設定を変更する処理は明示同意が
必要なため、初回起動ウィザードの責務として分離する。

## インストーラー基盤の採点

| 領域 | 配点 | 完了条件 |
|---|---:|---|
| 自己完結した配布物 | 25 | Java、本体、証明書生成ツール、依存関係、既定ファイルを同梱する |
| 対話・無人インストール | 15 | 同じMSIを画面操作と `msiexec /qn` の両方で導入できる |
| 単一製品ランチャー | 10 | 同梱JREから`NicoCacheLauncher.jar`を起動し、GUI、ヘッドレス、初回セットアップで入口を分けない |
| 安定した更新 | 15 | 固定Upgrade UUIDで旧版から新版へ更新し、ユーザー状態を保全する |
| 修復 | 10 | 削除された配布ファイルをMSI修復で復元し、ユーザー状態を保全する |
| 起動導線 | 10 | スタートメニューとデスクトップへ登録し、対話導入ではショートカットを選択できる |
| 安全な削除と検証 | 15 | 無人削除前に初回セットアップが変更したCA、プロキシー、自動起動を変更前へ戻し、製品ファイルとショートカットを残さない |
| **合計** | **100** | |

## 通常手順から初回起動ウィザードへ移す項目

- ユーザーデータ保存先の選択と、アプリ側 `config.properties` への記録
- 利用者側 `proxy.pac` の初期作成
- TLS MitM用CAとサイト証明書の生成
- CAをWindowsの現在ユーザー証明書ストアへ登録するかの選択
- Windows自動プロキシーを有効にするかの選択
- ログオン時の自動起動を有効にするかの選択
- 適用前のOS設定保存、取消、失敗時ロールバック、アンインストール向け復元情報

ウィザードの4つのOS連携項目は、現行ニコニコ動画を利用する推奨設定として初期状態を
ONにする。HTTPS MitMとCAの信頼登録はHTTPS通信に必須、`proxy.pac`は通常通信の性能を
保ち、ログオン時自動起動は手動起動の手間をなくすためである。

これらはMSIの無人導入中に暗黙で実行しない。GUI初回起動時に変更内容を表示し、
利用者が選択・確認した項目だけを適用する。製品GUIを使わない場合は同梱JREから
`NicoCacheLauncher.jar --setup --headless` に全選択を明示し、同じ適用・ロールバック処理を使う。
ただしCAの信頼登録を選んだ場合はGUIとヘッドレスのどちらでもWindows標準の
許可画面を表示し、利用者が承認した場合だけ登録する。許可画面を操作できない
自動試験ではCAを生成しても信頼登録は無効化し、証明書ストアが変わらないことを
検証する。
